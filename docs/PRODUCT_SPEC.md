# Nib 제품 명세

## 1. 제품 목표

문서 작성에 집중할 수 있는 로컬 우선 Markdown 에디터. Markdown 문법을 입력하면 즉시 서식이 적용되고, 편집 중인 요소만 원문 문법이 드러나는 경험을 목표로 합니다.

비목표(현 단계): 클라우드 동기화, 협업, 플러그인 시스템, 모바일, 웹 버전.

## 2. 대상 플랫폼

Windows, macOS 데스크톱. Linux는 요구사항이 아니며 지원 여부는 미정입니다.

## 3. 주요 기능

### MVP (초기 개발 범위)

| 기능 | 설명 |
|---|---|
| WYSIWYG 편집 | 제목, 굵게/기울임/취소선, 인라인 코드, 링크, 인용, 순서/비순서/체크리스트, 코드 블록, 구분선 |
| 입력 단축 | `# `, `- `, `> `, ` ``` ` 등 Markdown 입력 시 즉시 변환 |
| 파일 열기/저장 | 로컬 `.md` 열기, 저장, 다른 이름으로 저장, 변경 표시(unsaved) |
| 다중 창 | `Cmd/Ctrl+N` 새 창, `Cmd/Ctrl+O`는 빈 창이면 재사용·아니면 새 창, 같은 파일은 중복으로 열지 않음 |
| 저장 무손실 | 열고 저장했을 때 사용자가 편집하지 않은 부분의 Markdown이 불필요하게 바뀌지 않을 것 (검증 대상, ROADMAP Phase 0 참고) |
| 기본 앱 기능 | 창 메뉴, 단축키(저장/열기/굵게 등), 라이트/다크 테마(시스템 따라가기) |
| 글꼴 설정 | `Cmd/Ctrl+,`로 본문 글꼴(Open Sans·Pretendard·시스템)과 코드 글꼴(Cascadia Code·시스템 고정폭) 선택. 글꼴은 앱에 포함되어 오프라인에서도 동작 |

### 이후 (MVP 이후 후보, 우선순위 미정)

소스 모드 전환, 아웃라인, 수식(KaTeX), 다이어그램(Mermaid), 내보내기(HTML/PDF), 자동 저장/복구, 다중 탭.

## 4. UI/UX 방향

- 문서마다 창 하나, 본문 중앙 정렬(최대 폭 860px), 넉넉한 여백.
- 툴바 없음 또는 최소화. 서식은 Markdown 입력과 단축키가 기본.
- 폴더 트리 사이드바는 두지 않는다 (2026-10-28 결정: 미리보기 화면을 확인한 뒤 불필요하다고 판단). 문서 이동은 창 단위로 한다.
- 본문 타이포그래피: Open Sans(라틴)+시스템 한글 글꼴, 16px, 줄 간격 1.6, 글자색 #333, 자간 지정 없음, 최대 폭 860px(좌우 30px 포함), 제목 h1 2.25em·h2 1.75em·h3 1.5em·h4 1.25em·h5/h6 1em(제목 아래 구분선 없음).
- 크롬 요소는 조용하게: 낮은 대비의 구분선, 시스템 폰트 기반 UI, 본문은 가독성 높은 서체.
- 모든 Markdown 요소는 같은 규칙을 따른다: **문법이 완성되는 순간 서식을 적용**하고(`**굵게**`는 닫는 `**`가 입력될 때, 제목은 `# ` 공백이 입력될 때), **기호는 커서가 그 요소의 안쪽에 있는 동안만 보인다**(줄 단위가 아니라 요소 단위, 맨 앞/맨 뒤 위치는 제외). 닫는 기호를 입력하는 순간 서식이 적용되고 기호는 바로 숨는다.
- 편집 중인 요소만 원문 문법 노출은 핵심 경험이며, 엔진이 허용하는 범위에서 구현하며 범위는 Phase 1 검증 후 정합니다.

## 5. 성공 기준 (MVP)

- 일반적인 README급 문서(수백 줄)를 지연 없이 편집할 수 있다.
- 열기→(무편집)→저장 시 파일 내용이 의도치 않게 바뀌지 않는다(또는 바뀌는 항목이 문서화되어 있다).
- Windows, macOS에서 설치 없이 개발 빌드로 동일하게 동작한다.

## 6. 미결정 사항

- 소스 모드를 MVP에 포함할지
- Linux 지원 여부
- 정확한 테마/서체
- 앱 식별자(appId)와 배포 방식(서명, 자동 업데이트)
